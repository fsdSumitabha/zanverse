# Code to copy from the web app

## Numeric codes
NUMERIC CODE SYSTEM (every status/type/role is a number; labels live only in *_META maps; codes step by 10 so values fit between and are never renumbered).

ENTITY_TYPE (src/constants/entityTypes.ts) - 0 Lead, 1 Client, 2 Project, 3 User, 4 Interaction, 5 Meeting, 6 Document, 7 Call, 8 Quotation, 9 Lead Source (NEW), 10 Lead Source Upload (NEW). 9 and 10 are the lead-sources module additions; the polymorphic parent pair (entityType + entityId) still only ever uses 0/1/2.

LEAD_STATUS (leadStatus.ts) - 10 New Lead, 20 Contacted, 30 Meeting Scheduled, 40 Discussion, 50 Negotiation, 60 Converted, 70 Lost.
CLIENT_STATUS (clientStatus.ts) - 1 Active, 2 Inactive, 3 On Hold, 4 Completed (the only non-decade scale).
PROJECT_STATUS (projectStatus.ts) - 110 Discussion, 120 Proposal Sent, 130 Negotiation, 140 Confirmed, 150 In Progress, 160 Deployed, 170 Maintenance, 180 Closed.

INTERACTION_TYPE (interactionTypes.ts) - 2010 Meeting Scheduled, 2020 Meeting Rescheduled, 2030 Meeting Cancelled, 2040 Meeting Missed, 2050 Meeting Completed, 2110 Note Added, 2210 Call Made, 2310 Document Uploaded, 2410 Quotation Sent, 2510 Status Changed.
MEETING_STATUS (meetingStatus.ts) - 2010/2020/2030/2040/2050, intentionally identical to the meeting interaction codes so the meeting status route can write Interaction.type = meeting status directly.

CALL codes (callStatus.ts) exist only as map keys, with no const object or derived type: direction 0 Outbound / 1 Inbound (Call model enum [0,1]); status 0 Completed, 1 No Answer, 2 Busy, 3 Failed (not enum-validated in the model).
MEETING_TYPE (meetingTypes.ts) - 0 Online, 1 Offline.
Service (services.ts, a TS enum) - 10 Web Dev, 20 Marketing, 30 Blockchain, 40 Mobile App, 50 SEO.

EVENT_TYPE (eventTypes.ts, notifications) - 1000 LEAD_CREATED, 1010 LEAD_CONVERTED, 1020 LEAD_STATUS_CHANGED, 1100 CLIENT_CREATED, 1110 CLIENT_STATUS_CHANGED, 1200 PROJECT_CREATED, 1210 PROJECT_STATUS_CHANGED, 1500 INTERACTION_CREATED, plus every INTERACTION_TYPE code 2010-2510 spread in via invert(). EVENT_CODE is the reverse (name -> number) built so switch() on numbers still works. NOTIFICATION_RULES maps event -> roles: [10,30,45,60] for nearly everything, [10,45,60] for 2210 calls, [10,30,45,60,70] for 2410 quotations (accountants added).
NOTIFICATION_CHANNEL (notificationChannels.ts) - 2 Email, 3 SMS, 4 Web Push. Code 1 = in-app exists only as a comment in models/Notification.ts (`default: [/* IN_APP */]`); a mobile FCM channel would be a new code.

USER_ROLE_META (userRoles.ts) - 10 Admin, 15 Operations Manager, 20 HR, 30 Project Manager, 40 Full Stack Developer, 42 Blockchain Developer, 45 Senior Blockchain Developer, 50 Digital Marketer, 60 Business Development Executive, 65 US Sales Agent (NEW), 69 US Leads Manager (NEW), 70 Accountant, 80 Technical Support, 90 System Integration User (the automated creator of website/Facebook leads). The newest roles are 65 and 69, both US-region-specific. CROSS_REGION_USER_ADMIN_ROLES = [10, 20]: Admin and HR administer staff accounts in every region (and may grant any region), while their data access stays region-scoped. There is no USER_ROLE numeric const and no ROLE_GROUP file in this repo - permission arrays are inline in the API routes except for lead sources.
LEAD_SOURCE_ROLES (leadSourceRoles.ts) - MANAGE [10,15,45,69] (see all sources in their regions, upload sheets, assign person+day, delete), WORK [50,60,65,70] (only sources assigned to them: call, set status, note, callback), CONVERT [10,15,45,50,60,69,70] (65 deliberately excluded - it marks Interested and a manager converts). ACCESS = MANAGE + WORK. Region scope applies on top of every list.

LEAD_SOURCE_STATUS (leadSourceStatus.ts) - 10 New, 20 Not Reached, 30 Call Back, 40 Interested, 50 Not Interested, 70 Converted. No pipeline: any status can follow any other except CONVERTED, which only the convert route sets and nothing changes afterwards. 50 and 70 are flagged `closed: true` in the META map, which is what drives LEAD_SOURCE_OPEN_STATUSES / CLOSED_STATUSES (closed rows drop out of Today/Upcoming/No-day and stay in Closed/All); PICKABLE = everything except 70. 60 was Wrong Number, retired into 50 - never reuse 60, old rows may still hold it.
LEAD_SOURCE_ACTIVITY (timeline entry kinds) - 10 Uploaded, 20 Note, 30 Status, 40 Callback, 50 Assigned, 60 Day, 70 Converted (no META map; icons live in ActivityTimeline.tsx).
UPLOAD_ROW_RESULT - 10 Imported, 20 Imported with warnings, 30 Skipped (META also carries excelFill hexes #E2F5EA/#FFF4D6/#FDE2E2 for the xlsx report). UPLOAD_STATUS - 10 Processing, 20 Done, 30 Failed.

REGIONS (src/lib/region.ts, NOT in src/constants) - string codes, not numbers: "IN" India, "US" United States, "AE" United Arab Emirates, each with a libphonenumber-js phoneCountry; DEFAULT_REGION "IN"; ALL_REGIONS = "ALL" (label "Planet") is a view-only value that is deliberately not a RegionCode so it can never be written to the database or used in a query filter. Region currently comes from NEXT_PUBLIC_REGION via getRegion(); users hold regions[] and every list is region-scoped by regionScopePlugin.

STATUS_META_BY_ENTITY (statusMetaByEntity.ts) ties it together for the activity-log/status-change renderers: LEAD, CLIENT, PROJECT, MEETING, CALL and LEAD_SOURCE have status metadata; USER, INTERACTION, DOCUMENT and QUOTATION intentionally have none.

## Notes
- Read at ref commit 6858fb8 ("feat(lead-sources): add cold-calling lists, sheet upload, callbacks, and lead conversion merge"). Nothing was modified.
- Copy-as-is list (9 files, no changes needed): constants/_invert.ts, constants/entityTypes.ts, constants/eventTypes.ts, constants/leadSourceRoles.ts, constants/meetingTypes.ts, constants/userRoles.ts, types/leadSource.ts, types/meeting.ts, types/projects.ts (plus types/clients.ts, types/lead.ts, types/authProfile.ts, which copy cleanly but are missing the new region fields).
- Only ONE file in src/constants/** or src/types/** imports lucide-react: constants/callStatus.ts (`import * as Icons from "lucide-react"`, with `icon: keyof typeof Icons`). Because constants/statusMetaByEntity.ts re-exports CALL_STATUS_META, importing statusMetaByEntity from React Native drags lucide-react in transitively - split callStatus.ts first.
- Tailwind class strings appear in 8 *_META maps and must all get a mobile equivalent: LEAD_STATUS_META, CLIENT_STATUS_META, PROJECT_STATUS_META (label/color/decoration), INTERACTION_TYPE_META, MEETING_STATUS_META (label/icon/color), CALL_STATUS_META, SERVICE_META, LEAD_SOURCE_STATUS_META (color/dot) and UPLOAD_ROW_RESULT_META (chip/row). Suggested shape for RN: keep the numeric keys and `label` identical, replace `color` with {bg, fg} theme tokens and `decoration` with a borderColor, and keep the non-visual fields (`closed`, `excelFill`) where they are.
- The icon strings in INTERACTION_TYPE_META and MEETING_STATUS_META ("calendar", "refresh", "times", "exclamation-circle", "check", "file", "phone", "doc", "briefcase", "exchange-alt") are abstract FontAwesome-flavoured names, not lucide component names - they map to any RN icon set with a single lookup table. callStatus.ts is the exception: its icons ARE lucide component names.
- Server-only, do not bundle into the app: constants/notificationChannels.ts (imports the email/SMS/push dispatchers from @/lib), constants/notificationRules.ts (recipient resolution), types/notification.ts and types/quotation.ts (both import mongoose `Types`), types/facebook/facebook-leads.ts (webhook payloads).
