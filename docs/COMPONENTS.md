# Web component inventory and the React Native approach

92 files under src/components/admin/operations (excluding lead-sources/), ~10,940 lines; 88 .tsx + 4 pure .ts. Reference clone:  (main @ 6858fb8).

Counts per group: design-system primitives 15 | entity cards and lists 26 | forms 20 | modals and dialogs 6 | charts 6 | navigation and layout 4 | skeletons 11 | misc (pure TS, no UI) 4.

Complexity split: S 52, M 27, L 13.

Five heaviest components to port:
1. OverallStatsPanel.tsx (558 lines) — 3 Chart.js pie/doughnut charts, all canvas-only; needs a full chart-library rewrite (victory-native XL / gifted-charts) plus a file split.
2. activityLog/ActivityLogItem.tsx (453) — per-field old→new audit diff rendering, ImageKit <Image>, deep links per entity type, very dense flex/truncate layout.
3. MeetingCard.tsx (381) — three nested write flows (reschedule, complete-with-outcome, mark-missed), role gates, expandable history; should become a card + two bottom sheets.
4. InteractionModal/MeetingForm.tsx (359) — attendee picker fetching /users/picker with Set-based multi-select + search, plus datetime-local scheduling.
5. activityLog/ActivityHeatmap.tsx (285) — 371-cell GitHub-style grid with per-cell hover tooltips and horizontal overflow; needs SVG or a virtualized column ScrollView to stay smooth on low-end Android.
(Runners-up on porting difficulty rather than size: SearchBar.tsx and MobileNav.tsx — MobileNav is only 191 lines but is the most web-bound file in the tree, driven by window.scrollY, DOM measurement and a CSS-Module ::before/::after notch.)

Cross-cutting notes that affect the whole port:
- Dead code: statusSliders/LeadStatusSlider.tsx and the root StatusChangeItem.tsx have no importer anywhere in src — exclude them.
- Three filenames contain a trailing space before .tsx and are imported with it: "TemporalBadge .tsx", "Leadsovertimecard .tsx", "statistics/LeadsMonthlyChart .tsx". Rename during the port.
- External deps to replace: next/link + next/navigation (Link, useRouter, usePathname, useSearchParams, useParams) → React Navigation; lucide-react → lucide-react-native + react-native-svg; sonner → an RN toast (no toast.promise equivalent — write one wrapper); chart.js/react-chartjs-2 and recharts → an RN chart lib; react-dropzone → react-native-document-picker / image-picker; next/image and @imagekit/next → RN Image with ImageKit URL transforms; navigator.clipboard → @react-native-clipboard/clipboard; dayjs and clsx work unchanged.
- 6 components close themselves with document.addEventListener('mousedown'/'keydown') (Tooltip, SearchBar, NotificationBell, MobileTopBar, RegionSelect, RegionSwitcher) — all become Modal/bottom-sheet backdrops plus hardware-back handling.
- 5 components depend on native date inputs (filters/DateField, RescheduleMeetingForm, CallForm, MeetingForm, ListFilters) — one shared DateTimeField over @react-native-community/datetimepicker covers all of them.
- 3 filter components keep their state in the URL (ListFilters, MeetingFilters, SearchBar) — that state must move to screen state / query keys, a decision worth making before any list screen is written.
- Outside this folder but required first: src/components/phone/* (PhoneText, PhoneField, PhoneHint, useEditablePhone) and the AuthContext / RegionContext providers; also note region switching currently rides on a cookie, which should become an explicit header + AsyncStorage on RN (the Express backend already accepts Authorization: Bearer).
