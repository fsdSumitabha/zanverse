# Client-side systems and libraries

## Systems

### AuthContext (session + current user) — `src/contexts/AuthContext.tsx`
Client provider that calls GET /api/auth/me once on mount with credentials: "include" and cache: "no-store", and exposes { user, loading, isAuthenticated, role, regions, refreshUser, logout }. The AuthUser carries id, name, email, role (numeric), regions: RegionCode[], activeRegion: "IN"|"US"|"AE"|"ALL" and avatar. logout() POSTs /api/auth/logout, clears state, fires a sonner toast, then after a 500 ms setTimeout does router.push("/admin/authentication/login"). There is no token in JS anywhere — the session is the httpOnly auth_token cookie set by /api/auth/login (httpOnly, secure, sameSite lax, path /, maxAge 7 days).

**For React Native.** The whole shape ports cleanly (React context + fetch), but the cookie does not. React Native's fetch has no browser cookie jar you can rely on across Android/iOS, no httpOnly guarantee, and credentials: "include" is a no-op in many RN setups. Also there is no next/navigation router, so router.push must become a navigation action. The 500 ms toast delay before navigating is a web habit that will race with RN screen transitions.

**Recommendation.** Keep the context API identical (same field names, same /api/auth/me contract) so screens port unchanged, but swap the transport: have the Express backend also accept Authorization: Bearer (OVERVIEW §3.5 already plans this) and store the JWT in expo-secure-store / react-native-keychain. Write one apiClient module that injects the header and is the only place that knows about auth. Replace router.push with the navigation ref, and drop the setTimeout — show the toast and navigate immediately.

### RegionContext (multi-region session scoping) — `src/contexts/RegionContext.tsx`
Seeds from AuthContext (user.activeRegion, user.regions). setActive(next) POSTs /api/auth/region, which sets a second httpOnly cookie active_region (7 days) that requireAuth reads to narrow every API query. On success it trusts the server's returned value and then calls window.location.reload() — a deliberate full-page reload because every list on screen was fetched under the old scope. Exposes useRegion() (the single effective RegionConfig, "ALL" resolves to India) and useRegionScope() (regions, active, setActive, switching, isAll, canSwitch, config). Region codes and config live in src/lib/region.ts (IN/US/AE, each with a phoneCountry).

**For React Native.** window.location.reload() does not exist in React Native — this is the single hardest line in the client codebase to port. The cookie-based scope switch also breaks for the same reason as auth. And the invariant it protects (nothing on screen may outlive a region switch) is real: with a stack navigator, screens behind the current one keep stale, wrongly-scoped data.

**Recommendation.** Keep the context and the server contract (POST /api/auth/region stays authoritative). Replace the reload with an explicit cache reset: adopt a query cache (TanStack Query or SWR) from day one, and on a successful switch call queryClient.clear() plus popToTop() on the navigator. If you send the region as a Bearer-side header instead of a cookie, make the header part of every query key so a switch invalidates everything automatically. Do not try to emulate window.location.reload with a JS bundle restart.

### StatusContext (status-change remarks flow) — `src/contexts/StatusContext.tsx`
Tiny UI-only context: remarks, showRemarks, nextStatus, reset. Shared between a status dropdown and the remarks box so a pipeline move (lead/client/project) can collect remarks before the PATCH fires. No fetch, no browser API.

**For React Native.** None. Pure React state.

**Recommendation.** Port as-is, verbatim. It is the cheapest file in the migration.

### usePagination (URL-synced page state) — `src/hooks/usePagination.ts`
Reads ?page= via next/navigation useSearchParams, and setPage pushes a new URL (deleting the param when it equals the default so /leads stays canonical). setPage is referentially stable via a ref, deliberately, because callers put it in useEffect dependency arrays. The URL is the source of truth so reloads land on the same page and browser back/forward steps through pagination.

**For React Native.** The entire premise — the URL as state — does not exist in React Native. There is no shareable URL, no browser back stack stepping through query params, and useSearchParams has no equivalent. Android's hardware back button will exit the screen, not step back a page.

**Recommendation.** Rewrite as plain component state (or route params on React Navigation) with the same { page, setPage } signature so list screens do not change. Better: on mobile, replace numbered pagination with infinite scroll on a FlatList (onEndReached) fed by the same page/limit API — the backend pagination envelope { page, limit, total, pages } already supports it. Keep setPage stable (useCallback) to preserve the no-infinite-loop property.

### useSearch (URL-synced search term) + SearchBar — `src/hooks/useSearch.ts`
useSearch() just reads ?search= from useSearchParams. The writer is src/components/admin/operations/SearchBar.tsx: 300 ms debounce, mode switches on pathname (entity search on /leads, /clients, /projects, /meetings, /lead-sources; global dashboard search elsewhere, min 2 chars), and it pushes the param into the URL.

**For React Native.** Same URL-as-state problem. The pathname-driven mode detection also breaks — React Navigation gives you a route name, not a pathname string.

**Recommendation.** Make the search term local state in a useSearch hook with the same return type, keep the 300 ms debounce and the 2-character minimum (they shape server load), and derive the mode from the route name instead of a pathname regex. One shared SearchBar component on top of a FlatList header.

### handleAuthError (shared 401/403 handling) — `src/lib/auth/handleAuthError.ts`
Called by 15 files. On 401 it fires a sonner toast deduped by id "auth-401" (so parallel fetches do not stack three toasts) and router.replace("/admin/authentication/login"); on 403 it forwards the server message to the caller's onForbidden setter, which renders the AccessDenied UI. Returns true when handled so the caller early-returns. It takes a structural AuthRouter { replace } rather than the Next router type.

**For React Native.** Already loosely coupled — the structural router type is the only thing you have to supply. The toast dedupe-by-id is the only piece that depends on sonner specifically. The 401 path matters more on mobile: the Next proxy that normally redirects unauthenticated navigations does not exist, so every 401 now reaches this function.

**Recommendation.** Port nearly verbatim. Pass React Navigation's navigation ref as the AuthRouter ({ replace: (href) => navRef.resetToLogin() }). Keep the dedupe id. Centralise it inside the one apiClient so no screen can forget to call it — on mobile it should also clear the stored token from secure storage, which the web version did not have to do.

### Lead-sources fetch wrapper (send / ApiError) — `src/components/admin/operations/lead-sources/api.ts`
The newer lead-sources module uses its own client instead of handleAuthError: send<T>(url, method, body) sets Content-Type unless the body is FormData, unwraps { success, data }, throws a typed ApiError(message, status, field, details) so the caller can show the server's message and highlight the offending field, and on 401 toasts then does window.location.href = LOGIN_PATH. Exports LEAD_SOURCES_API and LEAD_SOURCES_PAGE constants.

**For React Native.** window.location.href does not exist in React Native. Otherwise this is the better of the two client patterns and the FormData branch already matches what RN needs for file upload.

**Recommendation.** Make this the single API client for the whole RN app and retire the handleAuthError-per-screen pattern during the port: same send() signature, same ApiError (the field property drives inline form errors), with the 401 branch doing secure-storage clear + navigation reset. One file, one place that knows about auth, base URL and the error envelope.

### Notification polling (bell + unseen/unread counts) — `src/components/admin/operations/NotificationBell.tsx`
setInterval every 30 s (POLL_INTERVAL_MS = 30_000) calling GET /api/notifications?limit=4 with cache: "no-store". Tracks unseen (red bubble on the bell) and unread (list styling) separately. Opening the panel optimistically zeroes unseen and PATCHes /api/notifications/seen; marking one read PATCHes /api/notifications/:id/read; mark-all PATCHes /api/notifications/read-all; every mutation is optimistic and re-fetches on failure. The panel is an absolutely positioned dropdown closed by a document mousedown listener and an Escape keydown listener. Badge icons come from NotificationBadge.tsx, which maps badge strings (and legacy emoji) to lucide icons. src/lib/notifications/channels/push.ts exists but only console.logs — push is not implemented.

**For React Native.** A 30 s setInterval keeps running when the app is backgrounded on Android and will be throttled or killed unpredictably; it also drains battery and burns mobile data for a CRM people leave open all day. document mousedown / keydown close handlers have no RN equivalent (no document, no Escape key). The absolute dropdown must become a modal or bottom sheet. The optimistic-update logic itself is good and portable.

**Recommendation.** Keep the API contract and the optimistic logic exactly. Replace the raw interval with AppState-aware polling: poll only while AppState is "active", and refetch immediately on background→active transition instead of on a fixed tick. This is where the Android port can beat the web app — the push channel is already stubbed server-side, so wire FCM (Notifee / @react-native-firebase/messaging) into dispatchPush and make the bell a cache-refresh target rather than a poller. Replace the dropdown with a bottom sheet; drop the mousedown/Escape listeners entirely.

### Region switching UI — `src/components/admin/operations/region/RegionSwitcher.tsx`
Pill in the header. Someone holding one region gets a non-interactive badge (deliberate: a one-entry dropdown is worse than none); canSwitch gates the dropdown. Options are ["ALL", ...regions]. Renders nothing until /api/auth/me returns, so a wrong region never flashes. Closed via document mousedown + Escape listeners. A compact prop renders flag-only for the mobile header. Flags come from RegionFlag.tsx, which imports country-flag-icons/react/3x2/{IN,US,AE} one at a time (explicitly chosen over emoji because Windows has no flag glyphs, and over lucide which has no flags); "ALL" gets a lucide Globe. WriteRegionField.tsx + useWriteRegion pick the region a new record is saved in, mirroring the server's resolveWriteRegion rule.

**For React Native.** Three things break: the document event listeners, the absolutely positioned role="listbox" panel, and the SVG flags (country-flag-icons ships React components built on <svg>/<path> DOM elements, which RN cannot render without react-native-svg). The switching Loader2 spinner also relies on a CSS animate-spin class.

**Recommendation.** Rebuild the switcher as a React Navigation header button opening a bottom sheet / ActionSheet — closing is handled by the sheet, so the listeners disappear. For flags, do not pull in country-flag-icons: there are only three (IN, US, AE), so bundle three static PNG/SVG assets (react-native-svg if you want SVG) and keep the RegionFlag component signature identical. Keep the "render nothing until /api/auth/me returns" rule — it is load-bearing. Keep WriteRegionField's pinned logic verbatim; it prevents a save-then-404.

### Phone input handling — `src/components/phone/PhoneField.tsx`
The most engineered part of the client. PhoneField wraps react-phone-number-input with international={false} (local format only, "+" cannot be typed), initialValueFormat="national", addInternationalOption={false}, no limitMaxLength (so an extra digit surfaces a "too long" error instead of being silently truncated), countryOptionsOrder = [IN, US, AE, divider, rest], and a custom CountrySelect.tsx that replaces the library's picker with a native <select> using two <optgroup>s (Suggested / All countries) and shows the calling code ("+1") beside the flag. onKeyDown blocks the "+" key with an explanatory message; onPaste runs checkPastedPhone before the input mangles the text (the library would turn "Call after 6pm: 415 555 0146" into a different number). useEditablePhone.ts holds form state and the check() contract: it reads inputRef.current.value (the typed text) rather than trusting the library's value, returns the untouched savedPhone when unchanged so legacy rows like "9876543210" or "N/A" do not block editing other fields, and otherwise returns E.164. PhoneText.tsx renders saved numbers (valid → formatted, optionally a tel: link; invalid → muted, never a link). All the real logic is in src/lib/phone.ts (pure libphonenumber-js, no DOM, strips zero-width/RTL marks, maps "00" to "+", extract: false, typed PHONE_MESSAGES). Styling is ~80 lines of .phone-field CSS overrides in globals.css including a dark-mode block.

**For React Native.** react-phone-number-input is a DOM component (<input>, <select>, <optgroup>) and will not render in React Native at all — this is a full rewrite of the UI layer. The CSS overrides are dead. inputRef.current.value, onPaste and clipboardData have no RN equivalent (RN TextInput has no paste event), so the paste-guard — which exists to stop a real data-corruption bug — has to be re-implemented as an onChangeText guard. scrollIntoView in showError is also web-only.

**Recommendation.** Split the port in two. src/lib/phone.ts and useEditablePhone's check()/validate logic are pure TypeScript on libphonenumber-js — copy them across byte-for-byte, they are the valuable part. Rebuild only the field: a plain TextInput (keyboardType="phone-pad") plus a country bottom-sheet picker showing IN/US/AE first then the rest, preserving every rule: no "+" accepted, no silent truncation, local format only, same PHONE_MESSAGES strings. Move the paste guard into onChangeText (detect a multi-character jump and run checkPastedPhone on the delta). Replace scrollIntoView with a ScrollView ref measure/scrollTo.

### Cookie-based auth and the Next proxy RBAC gate — `src/proxy.ts`
Two httpOnly cookies carry the whole session: auth_token (JWT { userId, role }, 7 days) and active_region. No token or user data is ever in JS-readable storage — there is zero localStorage, sessionStorage or document.cookie usage anywhere in src. src/proxy.ts runs before every /admin navigation: it jwtVerifies the cookie, redirects anonymous users to the login page, redirects an already-logged-in user away from /login, and enforces a routePermissions table of regex → numeric role arrays (users, leads/create, convert, edit pages, lead-sources upload/uploads) with a redirect to /admin/authentication/unauthorized. Server handlers re-check with requireAuth/requireRole, so the proxy is defence in depth, not the only gate.

**For React Native.** No proxy equivalent exists in React Native — every route guard the proxy performed silently now has to be expressed in the navigator. The httpOnly cookie, which is the app's main XSS defence on web, cannot be used; the token will live in app storage instead, so the threat model changes (device compromise / rooted device rather than XSS).

**Recommendation.** Store the JWT in react-native-keychain / expo-secure-store (never AsyncStorage) and send it as Authorization: Bearer, which the Express port is already designed to accept. Port routePermissions verbatim into a shared canAccess(role, routeName) helper and use it in two places: to filter the tab/drawer items (SideBar.tsx and MobileNav.tsx already filter nav items by role arrays — same source of truth) and as a guard inside each screen. Keep the server-side requireRole as the real gate; treat the client check as UI only. Also handle 7-day expiry explicitly: on mobile there is no navigation redirect to catch it, so the 401 path in the API client is now the only backstop.

### Direct browser-API usage outside the contexts — `src/components/admin/operations/lead-sources/Popover.tsx`
A small, enumerable set. Popover.tsx: createPortal into document.body, getBoundingClientRect positioning, flip-up-when-no-room-below, ResizeObserver, window resize + capture-phase scroll listeners, and below 640 px it becomes a bottom sheet with pb-[env(safe-area-inset-bottom)]. Tooltip.tsx: same window.innerWidth/innerHeight measuring + portal. MobileNav.tsx: window.scrollY with requestAnimationFrame to hide/show the bottom bar on scroll, plus a window resize handler to compute an indicator gap. MeetingLinkButton.tsx and lead-sources/dialer.ts: navigator.clipboard.writeText. WhatsAppLink.tsx: navigator.userAgent sniffing to choose whatsapp://send?phone= on mobile vs https://web.whatsapp.com/send. BookingClient.tsx: window.matchMedia("(max-width: 767px)"). AvatarPreview.tsx: URL.createObjectURL. AnimatedItem.tsx: a per-index setTimeout(index * 120) staggered fade-in. useNow.ts: setInterval every 20 s so "in 5 min" callback chips tick to "due" without a server round trip. Dark mode is CSS @media (prefers-color-scheme: dark) throughout.

**For React Native.** Portals, getBoundingClientRect, ResizeObserver, scroll listeners, matchMedia and env(safe-area-inset-*) all have RN counterparts but none are drop-in. The upside: Popover already has a phone branch (bottom sheet below 640 px) and WhatsAppLink already has the mobile deep link — on RN those become the only branch, which deletes code. navigator.clipboard and URL.createObjectURL need libraries.

**Recommendation.** Map them one by one: Popover/Tooltip → react-native-modal or @gorhom/bottom-sheet (delete the desktop positioning branch entirely, keep only the sheet); MobileNav → React Navigation bottom tabs (the hide-on-scroll and indicator maths can go); clipboard → @react-native-clipboard/clipboard; WhatsAppLink → Linking.openURL("whatsapp://send?phone=") with canOpenURL as the fallback test instead of userAgent sniffing, and tel: links in PhoneText → Linking.openURL; matchMedia → useWindowDimensions; env(safe-area-inset-bottom) → react-native-safe-area-context (already in your package.json); AnimatedItem → a LayoutAnimation or Reanimated entering animation with the same 120 ms stagger; useNow → keep as-is but pause it on AppState background, same as the notification poller; prefers-color-scheme → useColorScheme() from RN, which maps cleanly.

### Service worker and PWA manifest — `public/sw.js`
src/app/sw-register.tsx registers /sw.js on mount (silently ignoring failure). public/sw.js is a cache-v1 worker: precaches an offline.html and the icons, skipWaiting + clients.claim, ignores non-GET, explicitly never caches /api/* ("a CRM must always show fresh data"), network-first with offline fallback for navigations, and stale-while-revalidate for static assets. src/app/manifest.ts declares a standalone PWA named "Zan CRM" with theme #183668, 192/512 icons and three app shortcuts (Leads, Clients, Meetings).

**For React Native.** All of it is dead on React Native — no service worker, no web manifest, no Cache API. But the intent behind it is exactly what a native app is for, and the manifest doubles as a spec: it tells you the app name, the brand colour (#183668 / light #4A6FA5) and which three screens deserve Android app shortcuts / quick actions.

**Recommendation.** Delete sw.js and sw-register entirely. Carry the intent over: the no-cache-for-/api rule becomes your query cache policy; the offline fallback becomes NetInfo + an offline banner; the icons and theme colour go into the Android adaptive icon and status bar; the three manifest shortcuts become Android app shortcuts (shortcuts.xml). Note the web app has no real offline data story (API responses were never cached) — do not promise one in v1; a cached read-only list via TanStack Query persistence is a reasonable later step.

### File upload and spreadsheet download (lead-sources) — `src/components/admin/operations/lead-sources/UploadForm.tsx`
UploadForm.tsx uses react-dropzone (single file, maxSize from LEAD_SOURCE_SHEET_RULES.maxFileMb, accept .xlsx/.csv) and posts a FormData with file, today, region, assignedTo, allottedDay to POST /lead-sources/uploads, rendering server-returned header problems (missing/found columns) inline. The generic FileUpload.tsx (dropzone, 5 MB, image/jpeg+png) is used for avatars. Parsing is server-side only (read-excel-file in src/lib/lead-sources/sheet/readSheet.ts, using the /universal entry because the node entry broke Turbopack tracing). The upload report is downloaded by a plain href to .../uploads/:id/download, which streams an xlsx built by write-excel-file/node.

**For React Native.** Drag-and-drop is meaningless on a phone, and there is no File object or <a download>. RN FormData can post a file but takes { uri, name, type }, not a File. Opening an .xlsx on Android needs a download + external viewer intent.

**Recommendation.** Replace both dropzones with react-native-document-picker (sheets) and react-native-image-picker (avatars) behind the same { file, setFile } prop shape, so the surrounding form logic is untouched. Enforce the same maxFileMb and extension rules client-side before posting. Build FormData with the { uri, name, type } shape. For the report, use react-native-blob-util / expo-file-system to download with the auth header, then open with the system viewer — a bare href will not carry the token. All the parsing stays on the server, which is the right call and needs no change.

## Browser assumptions to replace
- The session is two httpOnly cookies (auth_token JWT 7 days, active_region) set by the server. No token or user data is ever in JS-readable storage — there is zero localStorage, sessionStorage or document.cookie usage in the entire src tree. React Native has no equivalent, so the whole app must move to Authorization: Bearer plus secure device storage.
- src/proxy.ts does route-level RBAC on every /admin navigation (regex → numeric role arrays) before any React code runs. React Native has no such layer; those rules have to be re-expressed in the navigator and in nav-item filtering, with the server's requireRole remaining the real gate.
- URL-as-state: usePagination and useSearch keep page and search in the query string via next/navigation, relying on shareable URLs and browser back/forward. None of that exists in RN; both hooks need rewriting to local or route state.
- RegionContext.setActive calls window.location.reload() to guarantee nothing stale from the previous region scope stays on screen. There is no reload in RN — the invariant has to be re-created with a query-cache clear plus a navigation reset.
- Dismiss-on-outside-click is implemented with document.addEventListener("mousedown") and Escape keydown in NotificationBell, RegionSwitcher, Popover and Tooltip. No document, no mouse, no Escape key on Android.
- Popover.tsx and Tooltip.tsx position themselves with createPortal into document.body, getBoundingClientRect, ResizeObserver, window.innerWidth/innerHeight and capture-phase scroll listeners. Popover already has a phone branch (bottom sheet below 640px) that should become the only branch.
- Notification polling is a bare setInterval of 30s (NotificationBell) and useNow is a 20s setInterval; both keep ticking when an Android app is backgrounded and will be throttled unpredictably. They need AppState gating, and the stubbed push channel (src/lib/notifications/channels/push.ts) is the better mobile answer.
- react-phone-number-input renders <input>, <select> and <optgroup>, and its behaviour is tuned by ~80 lines of .phone-field CSS in globals.css. It cannot render in RN at all. The paste guard depends on a clipboard paste event that RN TextInput does not have.
- country-flag-icons ships React components built on raw <svg>/<path> DOM elements; they will not render without react-native-svg, though only three flags (IN, US, AE) are actually used.
- Chart.js renders to <canvas>. Both chart files need a Skia or SVG charting library instead.
- File input is react-native-dropzone drag-and-drop over the File object, and the xlsx report is downloaded by a plain <a href> that authenticates via the ambient cookie. Both break: RN FormData needs {uri,name,type}, and the bare link will not carry a Bearer header.
- Dark mode is CSS @media (prefers-color-scheme: dark) throughout (Tailwind dark: classes plus a dark block in globals.css). Maps cleanly to RN useColorScheme(), but only if the styling layer is replaced wholesale or NativeWind is adopted.
- The PWA layer (public/sw.js, src/app/sw-register.tsx, src/app/manifest.ts) is entirely web-only and should be deleted, not ported. The manifest is still useful as a spec: app name "Zan CRM", theme #183668 / light #4A6FA5, and the three shortcut destinations (Leads, Clients, Meetings) are the natural Android app shortcuts.
- Smaller web-only touches: navigator.clipboard.writeText (MeetingLinkButton, lead-sources/dialer), navigator.userAgent sniffing to pick whatsapp:// vs web.whatsapp.com (WhatsAppLink — on RN it is always the deep link, via Linking), window.matchMedia (BookingClient), URL.createObjectURL (AvatarPreview), window.scrollY + requestAnimationFrame hide-on-scroll (MobileNav, replaced by bottom tabs), scrollIntoView in useEditablePhone's error path, title attributes used as tooltips in TimeAgo/PhoneText/RegionSwitcher, and tel: links in PhoneText (Linking.openURL).
- framer-motion (^12.38.0) and recharts (^3.8.1) are declared in package.json but have zero references anywhere in src or public — do not carry them into the RN project, and consider removing them from the web app.
